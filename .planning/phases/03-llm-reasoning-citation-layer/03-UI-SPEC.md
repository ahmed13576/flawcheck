# Phase 3 — UI Design Contract

> Visual and interaction contract for the Phase 3 reasoning surface: the reasoning pane per CML/reading, citation rendering against the `citations.json` allowlist, model badges + pipeline status line, and PT/MT triage narrative integration. Generated by gsd-ui-researcher; verified by gsd-ui-checker; consumed by gsd-planner, gsd-executor, gsd-ui-auditor.
>
> **Inherits the Phase 2 baseline verbatim** (`02-UI-SPEC.md`): forced dark theme tokens, 4px spacing scale, 3-type/2-weight typography, verdict/flag chip contracts, wizard chrome, accessibility floor items 1–10, and the no-new-packages checkpoint rule. This document is a **delta**: it only specifies what Phase 3 adds or changes. Out of scope: PDF report (Phase 4), demo caching / Live toggle (Phase 5), wizard Screens 1–2 (done in Phase 2).

**Reasoning text rendering (locked approach, `status: resolved (inferred)`):** the narrative renders as **plain text with inline citation tokens** — `[[cite:<citation_id>]]` — not Markdown. Rationale: a Markdown renderer would be a new dependency (forbidden without approval) and the only inline structure the narrative needs is citations; the token format is trivially parseable, renderer-enforced, and CI-checkable. The prompt template (lib-side) mandates the token format; the renderer is the only place tokens become visible chips.

## Reasoning-Pane Layout Contract

### Screen 3 region order (Phase 3 revision of the Phase 2 list)

1. Step indicator (unchanged)
2. Summary strip (unchanged)
3. **Pipeline status bar** (new — see Model Badge + Status-Line Contract)
4. CML results table — now **11 columns** (Phase 2's locked 10 keep their exact order; one trailing column added)
5. PT/MT triage list — each card gains a reasoning toggle + pane
6. Footnotes (unchanged + optional citation-audit line, see Copywriting)

### CML table extension

- New trailing column: `<th scope="col">Reasoning</th>` (11th; `colCount` 10 → 11 everywhere colSpan is used).
- Cell content: a compact toggle button — collapsed label `View reasoning`, expanded label `Hide reasoning` — `inline-flex h-6 items-center gap-1 rounded border border-[#262626] px-2 text-xs font-semibold hover:border-gray-500` with a 16px chevron inline SVG that rotates 180° when expanded (`transition-transform`; `motion-reduce:transition-none`). Same `aria-expanded` / `aria-controls` wiring as the flag-chip buttons; pane row id = `reasoning-${rowKey}` (uses the existing `resultRowKey` namespacing — duplicate Reading IDs stay safe).
- The pane renders as a full-width detail row (`colSpan={11}`) directly beneath the CML row — the FlagDetailRow pattern, extended. Multiple panes may be open at once; each toggle controls only its own row.

### Pane regions (top to bottom, inside the detail row)

Pane card: `rounded-lg border border-[#262626] bg-[#171717] p-4`, `aria-label` = `Reasoning for {readingId}`.

1. **Reasoning chain** (deterministic — rendered from the session's `ReadingResult`, never from LLM output; visible in every state including error/fallback). Four stacked blocks in fixed order, each: 12px uppercase muted step label + value line.
   - `INPUTS` — mono grid of the precomputed values: t-actual, t-pressure, t-structural, t-required, CR_LT, CR_ST, CR governing, RL (each `formatFixed` at table precision; `—` where null, never `Infinity`/`NaN`).
   - `CLAUSE` — CitationChips for `reading.citations[]` (Phase 2 engine already emits them), or `—` when the array is empty.
   - `LIMIT` — the governing limit statement: `t-required {value} mm ± {gauge uncertainty} mm gauge uncertainty` (gauge uncertainty from metadata), plus `CR governing {value} mm/yr` when history exists.
   - `VERDICT` — the row's `VerdictChip` (reused component) + computed basis text from the engine band, e.g. `t-actual 3.85 mm < t-required 4.20 mm`.
2. **Narrative region** (LLM-streamed or deterministic fallback — see states).
3. **Badge line** (bottom, 12px): per-reading model badge + `tokens {n} · {latency} s · {cost}` (mono, tabular-nums, `whitespace-nowrap`), plus any audit-stamp lines.

### Pane states (exhaustive)

| State | Chain | Narrative region | Badge line |
|-------|-------|------------------|------------|
| **loading** (pane open, first request in flight) | rendered immediately | `role="status"` muted line `Requesting narrative…` | empty |
| **streaming** | rendered | narrative text renders incrementally (`whitespace-pre-wrap break-words text-sm leading-normal`), trailing caret `<span className="ml-0.5 inline-block h-4 w-2 animate-pulse bg-[#a3a3a3] motion-reduce:animate-none" aria-hidden="true" />`; container `aria-busy="true"`; visible `role="status"` line `Streaming narrative…` | empty until usage metadata arrives |
| **complete** | rendered | full narrative with resolved CitationChips | model badge (runtime-resolved ID) + `tokens {n} · {s} s · {cost}` |
| **error** (request failed; layer reachable) | rendered — unaffected | `role="alert"` red text `Narrative unavailable: {reason}. The computed verdict is unaffected.` + neutral bordered button `Retry narrative` (pagination-button pattern) | empty |
| **fallback** (LLM layer unavailable / narrative rejected by lints) | rendered — unaffected | `DETERMINISTIC FALLBACK` chip + deterministic templated paragraph: the engine's inputs → clause → limit → verdict restated as prose (no LLM text) | `DETERMINISTIC FALLBACK` chip + `— — —` for tokens/latency/cost |

State transitions: loading → streaming → complete; loading/error → error → (Retry) loading; any → fallback when the gateway reports the layer unavailable or a lint rejects the narrative. Error and fallback are mutually exclusive and both leave the chain + verdict untouched.

### Streaming & caching behavior

`status: resolved (inferred)` — rationale: 4,912 readings make eager narration impossible and a "narrate all" button is not in scope; lazy-on-open with session caching is the simplest behavior consistent with the wizard's state-preserving navigation.

- Narratives stream **lazily**: only when a pane is opened for the first time.
- A completed narrative is cached in the wizard session; re-opening renders it instantly with **no new request**.
- Re-running the evaluation invalidates every cached narrative, closes all panes, and resets the pipeline status bar to `pending`.
- Pagination, sorting-free table layout, and flag detail rows behave exactly as Phase 2; opening a pane never triggers navigation or a table re-render of other rows.

## Citation Chip Contract

Sole resolution source: `lib/criteria/citations.json` (15-entry allowlist). The chip renders **only** fields from a resolved record — LLM free text can never enter the label.

### Resolved citation chip

- Label: `{code} {clause}` verbatim from the record (e.g. `ASME B31.3 304.1.2 (eq. 3a) & 304.1.1 (eq. 2)`, `API 574 Annex D, Tables D.2a-D.2d`, `API 570 Table 1 (per 6.3.3)`). No `§` is synthesized — the clause string is authoritative as stored. Long labels are allowed to be wide; the chip label is `whitespace-nowrap` and containers `flex-wrap`.
- Classes: `inline-flex h-6 items-center rounded border border-blue-600/30 bg-blue-600/10 px-2 text-xs font-semibold text-blue-400`.
- The chip is a real `<button type="button">` (keyboard parity): press toggles an **inline detail block** directly below the text block containing the chip (no absolute-positioned tooltip — it would clip inside the table's `overflow-x-auto`; this matches the Phase 2 flag-chip toggle pattern). `aria-expanded` / `aria-controls` wired to the detail id.
- Detail block content (12px): `{title}` (semibold) · `{code} — {edition}` · `verified {verified}` · `scope_note` (muted). One detail open per pane at a time.

### Unknown / fabricated citation (locked rule — renderer-enforced, CI-checked)

Roadmap SC3: "an unknown or fabricated ID renders blank with an audit stamp, never a plausible fake."

- The unresolved token renders **zero glyphs** at its position in the narrative (no chip shell, no placeholder text, nothing a reader could mistake for a reference). `status: resolved (inferred)` for placement: the blank is inline; the visible evidence lives in the audit stamp below.
- The pane's badge line gains an audit-stamp line (12px, amber-400 text on the default surface): `Unresolved citation blocked: '{id}' — rendered blank (audit {HH:mm:ss}).` This line is the stamp; it names the rejected ID so the failure is auditable, while the narrative body stays clean.
- The screen footnotes gain a summary line when any pane had rejections: `Citation audit: {n} unresolved citation(s) blocked at renderer.`
- CI check (planner note): a unit test renders a narrative containing an ID absent from `citations.json` and asserts (a) no code/clause-like text renders at the token position, (b) the audit stamp names the ID.

### Verbatim-text guard (cite-don't-quote, handoff §2.4)

The lib-side lint rejects narrative chunks matching verbatim standard text before they reach the client. UI contract: a lint-rejected narrative renders the **fallback** pane state (deterministic paragraph + `DETERMINISTIC FALLBACK` chip) — rejected text never partially renders.

## Model Badge + Status-Line Contract (PLAT-05)

### Badge classes

| Badge | Classes | Content |
|-------|---------|---------|
| Model badge | `inline-flex h-6 items-center rounded border border-gray-600 px-2 text-xs font-semibold text-gray-400` | runtime-resolved model ID string from the gateway response (e.g. the env-configured `NEBIUS_MODEL_REASONING` value) — **never a hardcoded ID** (Phase 1 invariant: repo grep for hardcoded model IDs must stay clean; the badge renders whatever the pipeline reports) |
| `DETERMINISTIC FALLBACK` | neutral chip base + `uppercase tracking-wide` | fixed label |
| `FAILED` | `inline-flex h-6 items-center rounded border border-red-500/30 bg-red-500/10 px-2 text-xs font-semibold uppercase tracking-wide text-red-400` | fixed label |
| Metrics text | `text-xs text-[#a3a3a3] font-mono tabular-nums whitespace-nowrap` | `tokens {n} · {latency} s · {cost}` |

### Per-step fields (exact)

| Step | Role label (fixed) | Badge | Fields |
|------|--------------------|-------|--------|
| Extraction | `Extraction` | model badge = resolved `NEBIUS_MODEL_EXTRACTION` value at call time | `tokens {n}` (prompt + completion, en-US grouping) · `{latency}` seconds, 1 dp · `{cost}` dollars, 4 dp (`$0.0031`) |
| Narrative | `Narrative` | model badge = resolved `NEBIUS_MODEL_REASONING` value; `DETERMINISTIC FALLBACK` chip when the fallback path served narratives | same three fields, aggregated across all pane requests in the session |
| Fallback | (no separate row — expressed on the Narrative row) | `DETERMINISTIC FALLBACK` chip replaces the model badge | metrics render `— · — · —` (never zeros presented as usage, never fabricated) |

Cost is supplied by the LLM layer (usage metadata); when pricing is unavailable the cost field renders `—` — the UI never computes or estimates cost. Latency and tokens likewise come from gateway usage metadata, not client timing.

### Status-line states (per step)

`pending` (muted text) → `running…` (muted text, `role="status"`) → complete (badge + metrics) / `FAILED` badge / fallback chip. `FAILED` on Extraction additionally raises the screen-level banner below.

### Placement + layout

Surface card between the summary strip and the results table: `rounded-lg border border-[#262626] bg-[#171717] p-4`, heading label `Pipeline` (12px uppercase muted), one row per step: role label (14px) + badge + metrics, `gap-2`, wrapping. On Screen 3 arrival (before any pane is opened) both steps render `pending`.

### Extraction failure (loud, REAS-01 / SC1)

When Lightning extraction fails validation after its one bounded retry, narration never starts: a `role="alert"` banner renders above the results table — `Extraction failed: {message}. Narrative generation was skipped — verdicts below are computed and unaffected. Correct the input and re-run the evaluation.` — the Extraction step shows the `FAILED` badge, every pane renders its error state on open, and the table's computed columns remain fully populated.

## Accessibility Floor (delta — Phase 2 items 1–10 all stand; additions)

11. Every reasoning toggle and citation chip is a real `<button>` with `aria-expanded` / `aria-controls`; focus order stays DOM order (toggle button → its detail row is the immediately following DOM).
12. The narrative container sets `aria-busy="true"` while streaming; state changes are announced via a single `role="status"` line (the streamed text itself is NOT a live region — re-announcing every chunk would be unusable). Errors use `role="alert"` (narrative error, extraction-failure banner).
13. Citation chips are keyboard-operable (Enter/Space toggle the inline detail); the detail block is adjacent in DOM order.
14. `DETERMINISTIC FALLBACK`, `FAILED`, and verdict/flag semantics are always carried by text — color and animation are never the sole channel.
15. `prefers-reduced-motion`: the streaming caret renders static (`motion-reduce:animate-none`), the chevron rotation is instant (`motion-reduce:transition-none`).
16. Contrast: `text-blue-400` on `bg-blue-600/10` over `#171717`, `text-gray-400` on `#171717`, and `text-amber-400` audit stamps all ≥ 4.5:1.
17. Focus remains on the toggle button when the pane opens/closes (no focus stealing); the pane region carries `aria-label="Reasoning for {readingId}"`.
