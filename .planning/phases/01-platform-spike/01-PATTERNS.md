### `lib/llm/complete.ts` + `lib/llm/schemas.ts` (service, request-response retry)

**Analog:** none — greenfield. **Source:** RESEARCH.md Pattern 2 (lines 231-274). This is the phase's central reusable pattern; copy the excerpt essentially verbatim.

**Core pattern** (lines 236-274) — injectable client, `json_object`, schema-in-prompt, exactly one bounded retry, clear final error:

```ts
export interface ValidatedCallOptions<T> {
  client: OpenAI;                      // injected — offline tests pass a fake
  model: string;                       // env-configured ID
  system: string;
  user: string;
  schema: ZodType<T>;
  schemaHint: string;                  // human-readable JSON shape to include in the prompt
  maxCompletionTokens?: number;
  reasoningEffort?: "low" | "medium" | "high";  // low|medium|high ONLY (verified 2026-09-26)
}

export async function runValidatedCompletion<T>(o: ValidatedCallOptions<T>): Promise<T> {
  const messages = [
    { role: "system" as const, content: `${o.system}\nRespond ONLY with JSON matching this shape:\n${o.schemaHint}` },
    { role: "user" as const, content: o.user },
  ];
  const call = (extra: object) => o.client.chat.completions.create({
    model: o.model,
    messages,
    response_format: { type: "json_object" },
    ...(o.maxCompletionTokens ? { max_completion_tokens: o.maxCompletionTokens } : {}),
    ...(o.reasoningEffort ? { reasoning_effort: o.reasoningEffort } : {}),
    ...extra,
  });

  let lastError: string = "";
  for (let attempt = 0; attempt < 2; attempt++) {          // exactly one bounded retry
    const res = await call(attempt === 1
      ? { messages: [...messages, { role: "user" as const, content: `Your previous reply failed validation: ${lastError}. Reply again with corrected JSON only.` }] }
      : {});
    const raw = res.choices[0]?.message?.content ?? "";
    try {
      return o.schema.parse(JSON.parse(raw));
    } catch (e) {
      lastError = e instanceof Error ? e.message : String(e);
    }
  }
  throw new Error(`Validated call failed after 1 retry (model=${o.model}): ${lastError}`);
}
```

**Error-handling contract:** final thrown error names the model AND carries the Zod message (line 273) — the offline test asserts exactly this (line 435). `schemas.ts` holds the spike Zod schemas (e.g., `HelloSchema` shown in Pattern 6, line 418).

### `app/api/spike/stream/route.ts` (route handler, streaming SSE)

**Analog:** none — greenfield. **Source:** RESEARCH.md Pattern 3 (lines 282-311).

**Core pattern** (lines 287-311):

```ts
import { getClient } from "@/lib/llm/client";
import { getReasoningModel } from "@/lib/llm/config";

export const runtime = "nodejs";

export async function POST(req: Request) {
  const { prompt } = await req.json();
  const client = getClient();
  const model = getReasoningModel();
  const encoder = new TextEncoder();

  const stream = await client.chat.completions.create({
    model, messages: [{ role: "user", content: prompt }],
    stream: true, max_completion_tokens: 2000, reasoning_effort: "low",
  });

  const sse = new ReadableStream({
    async pull(controller) {
      for await (const chunk of stream) {
        const delta = chunk.choices[0]?.delta?.content ?? "";
        if (delta) controller.enqueue(encoder.encode(`data: ${JSON.stringify({ text: delta })}\n\n`));
      }
      controller.enqueue(encoder.encode("data: [DONE]\n\n"));
      controller.close();
    },
  });
  return new Response(sse, { headers: { "Content-Type": "text/event-stream", "Cache-Control": "no-cache" } });
}
```

Validation note (ASVS V5, line 549): validate `request.json()` body before use — the excerpt reads `{ prompt }` unvalidated; add a minimal check (e.g., non-empty string) at the parse boundary.

### `app/spike/page.tsx` (component, streaming consumer)

**Analog:** none — greenfield. **Source:** RESEARCH.md Pattern 3 client half (lines 314-335) + Pattern 4 red-banner spec (line 369).

**Core consumption pattern** (lines 316-335):

```ts
"use client";
async function runSpike(prompt: string) {
  const res = await fetch("/api/spike/stream", { method: "POST", body: JSON.stringify({ prompt }) });
  const reader = res.body!.getReader();
  const decoder = new TextDecoder();
  let buf = "";
  for (;;) {
    const { done, value } = await reader.read();
    if (done) break;
    buf += decoder.decode(value, { stream: true });
    for (const line of buf.split("\n\n")) {          // SSE events are \n\n-separated
      if (line.startsWith("data: ")) {
        const payload = line.slice(6);
        if (payload === "[DONE]") return;
        appendText(JSON.parse(payload).text);        // render incrementally
      }
    }
    buf = buf.slice(buf.lastIndexOf("\n\n") + 2);
  }
}
```

Red-banner behavior (line 369): poll `/api/health` on mount; on `status === "degraded"` render fixed red banner: `Model routing invalid — missing: <ids>. Update .env.local / Vercel env vars.`

## Shared Patterns

### 1. Env-only model configuration (no hardcoded IDs)
**Source:** RESEARCH.md Pattern 1 (lines 197-209) + Pitfall 6 (lines 480-483) + grep gate (line 201)
**Apply to:** every file that references a model (`config.ts`, `client.ts`, `complete.ts`, both routes, both tests, scripts, `instrumentation.ts`)

- Gate: `grep -rn "nvidia/" app/ lib/ scripts/ tests/ instrumentation.ts` must return zero hits (targets `*.ts *.tsx *.mjs *.mts` only; `.env.example` is exempt)

### 2. Server-only secrets
**Source:** RESEARCH.md Security Domain (lines 552-560)
**Apply to:** `lib/llm/*`, both route handlers, `.gitignore` merge
- API key read only inside `lib/llm/*`; no route returns it; `/api/health` returns booleans + missing IDs only; never `NEXT_PUBLIC_` on `NEBIUS_API_KEY`; `.env*` gitignored before first install

### 3. Error conventions (three tiers)
**Source:** RESEARCH.md Patterns 1, 2, 4
**Apply to:** config (throw), LLM calls (bounded retry then throw), health (degraded response)
- Config accessors: `throw new Error("Missing required env var: <NAME>...")` (lines 216-219)
- Validated calls: after exactly 1 retry, `throw new Error("Validated call failed after 1 retry (model=<id>): <zod message>")` (line 273)
- Health: HTTP 503 + `{status: "degraded", missing: [...], checkedAt}` (lines 360-366); startup validation logs but never crashes (lines 347-350)

### 4. Zod at every parse boundary
**Source:** RESEARCH.md ASVS V5 row (line 549), Pattern 2 (line 268)
**Apply to:** `lib/llm/schemas.ts`, `complete.ts`, route-handler body parsing
- Model output parsed via `schema.parse(JSON.parse(raw))`; `request.json()` bodies validated before use

### 5. API-parameter discipline
**Source:** RESEARCH.md Corrections C1/C2 (lines 120-121) + Pitfall 1 (lines 454-458)
**Apply to:** `complete.ts`, `spike/stream/route.ts`, fixture tests
- `reasoning_effort` typed as `"low" | "medium" | "high"` ONLY (no `none`/`xhigh` — 422 otherwise)
- `response_format: {type: "json_object"}` is the guaranteed mode; `json_schema` result is unknown — the spike record (line 437) captures the live one-off attempt

### 6. Import alias and layer invariants
**Source:** RESEARCH.md tree conventions (line 195)
**Apply to:** all new `.ts` files
- Alias `@/*` → `./*` (e.g., `@/lib/llm/client`); `lib/calc/` must never import `lib/llm/` (do not violate from day one); `lib/criteria/` untouched this phase

### 7. Committed-JSON artifact style
**Source:** `lib/criteria/ut-criteria.json` / `citations.json` (git-tracked; formatting conventions extracted above)
**Apply to:** `docs/model-catalog.json`
- 2-space indent, ISO timestamp + count header, provenance-style metadata, trailing newline
