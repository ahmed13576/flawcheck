## Verdict Glossary Contract

**One shared source of truth:** `VERDICT_GLOSSARY: Record<Verdict, { plain: string; citationId: string | null }>` exported from `lib/report/content.ts` (the established server-safe seam) and consumed by all three renderers: `screen-results.tsx` (Screen 3 footer), `report-document.tsx` (conclusions section), `pdf-document.tsx` (page-1 footer). Import-graph is asserted by test — one constant, three renderers, zero drift.

**Locked copy verbatim** (plain sentence FIRST, clause sub-line beneath composed ONLY via `citationRef(citationId)` — hardcoded clause strings are forbidden; citation ids are the research REMAP, verified against `citations.json`):

| Verdict | Plain sentence (locked) | citationId (locked) | Rendered sub-line |
|---------|------------------------|---------------------|-------------------|
| ACCEPT | Wall thickness meets the code minimum at this location. | `api574_10_5_1_4` | `API 574 §10.5.1.4` |
| RE-CHECK | Thickness is close to the limit — re-measure to confirm before deciding. | `api570_7_1_2_governing` | `API 570 §7.1.2` |
| FAIL | Wall is thinner than the code allows at this location. Action required. | `api570_7_6` | `API 570 §7.6` |

Entries render in the fixed order ACCEPT, RE-CHECK, FAIL. Chip strings `ACCEPT / RE-CHECK / FAIL` in `verdict-chip.tsx` are repo-protected and UNCHANGED — the glossary renders adjacent (footer/block level), never inside a chip, and never renames a chip. `verdictLabel()` output is untouched.

### Surface layouts

1. **Screen 3 — results table footer.** A block directly beneath the `ResultsTable`, above the mono unit/source footnotes. Per entry one line: colored dot (`text-accept` / `text-recheck` / `text-fail`, matching the existing dot legend) + verdict word (`text-xs font-semibold`) + em-dash + plain sentence (`text-xs text-muted-foreground`); the clause sub-line sits directly beneath in `font-mono text-xs text-muted-foreground`. Real text — never a tooltip, image, or `title` attribute.
2. **HTML report — conclusions section.** A glossary block at the end of the "Clause-cited conclusions" section (after the `<ol>` or its empty-state line): same three entries, `text-xs text-muted-foreground`, mono clause lines. Renders on the light island using light tokens — same contrast floor applies.
3. **PDF — page-1 footer.** Last block of the dashboard page: a small label `Verdict glossary` followed by three entries — plain sentence at `fontSize: 7` (`styles.footer` family), clause sub-line beneath in `styles.monoSmall` (Courier). Composed by `citationRef`; if an id ever fails to resolve, the sub-line renders empty (zero glyphs) and the test suite fails — never a hardcoded fallback string.

## Screen 3 — "What we found" Brief (region contract)

### Placement and container

The brief mounts directly below the hero card ("Your findings are ready" — which holds the page heading) and ABOVE the "Finding metrics" KPI cards, inside the existing Screen 3 stack — first thing the eye lands on after evaluation (CONTEXT locked position), above the results table. Container: the Screen 3 content column (`max-w-6xl` centered, existing wizard shell — unchanged) and:

```
<section aria-label="What we found" className="flex flex-col gap-2 rounded-xl border border-border bg-card p-6">
```

No max-width of its own (spans the column); no new border/radius/shadow — `bg-card border-border rounded-xl` exactly.

### Internal structure (fixed order)

1. **Disposition line** — `text-lg font-semibold` (`text-foreground`).
2. **Next-action line** — `text-sm font-semibold` (`text-foreground`), prefixed `Next action: `.
3. **Narrative paragraph** — `text-sm text-muted-foreground`, 2–3 sentences: counts by verdict and what each verdict means (uses the glossary's plain sentences as the "meanings").
4. **Worst-locations list** — a real `<ul>` of at most 5 `<li>` rows, one line each: location name (`font-mono text-sm`, `truncate` + `title`) + `<VerdictChip>` + plain-why (`text-sm text-muted-foreground`). Rows never wrap into two visual lines for the name; the why-phrase may wrap.

**Citation invariant:** ZERO clause citations anywhere in the brief — no `citationRef`, no citation chips, no `[[cite:]]` tokens. The tables below carry all citations. The brief is deterministic TypeScript composed from `evaluate()` output (`summary` + `readings`) — NOT LLM-generated; no narrative-store, telemetry, or `Date.now` input reaches it. The Nemotron per-CML reasoning pane continues to exist beside it, untouched.

### Worst-list ordering (locked — mirrors `getGoverningPdfReadings` conventions)

`immediate_inspection` readings first → rejects before re-checks → `rlYears` ascending → null-RL last within its verdict class (null means "no computable life", never "infinite"). Cap = `min(5, non-accept count)`; when ≤ 5 non-accept readings exist, list them all. All-accept sessions render an EMPTY list (no placeholder row).

### Plain-why strings (locked derivation — priority order, first match wins)

| Condition | Why string |
|-----------|-----------|
| FAIL + `immediate_inspection` flag | No safe service life remaining |
| FAIL, structural-governed (`tRequiredMm` == `tStructuralMm` at 6 dp) | Below the structural minimum thickness |
| FAIL, otherwise (pressure-governed) | Below the pressure-design minimum thickness |
| RE-CHECK with `insufficient_history` flag | Not enough survey history to compute remaining life |
| RE-CHECK, otherwise | Within the gauge-uncertainty band — re-measure to confirm |
| Any reading with `outlier` flag (appended as its own list row if non-accept) | Reading deviates from this CML's history — re-shoot candidate |

`summary.locations` counts mapped tanks, not CMLs — it is never called "CMLs" in the brief; the disposition sentence cites READING counts, the worst list cites CML/grid names.

### Copy contracts — the three canonical cases (verbatim rendered examples)

**Case 1 — all accept (example: 420 readings, all ACCEPT):**

> All 420 readings meet the code minimum.
> Next action: continue the established inspection interval — the earliest next inspection is dated in the register.
> All 420 readings are ACCEPT — wall thickness meets the code minimum at every measured point.
> *(worst-locations list: absent)*

**Case 2 — mixed (example: 420 readings — 409 ACCEPT, 9 RE-CHECK, 2 FAIL):**

> 2 of 420 readings failed — immediate inspection required at the worst locations listed below.
> Next action: re-measure the failing locations and disposition them against the code before continued service.
> 409 readings are ACCEPT — wall thickness meets the code minimum. 9 are RE-CHECK — thickness is close to the limit and must be confirmed. 2 are FAIL — wall is thinner than the code allows.
> S6-G07 [FAIL] No safe service life remaining
> S6-G11 [FAIL] Below the pressure-design minimum thickness
> S6-G03 [RE-CHECK] Within the gauge-uncertainty band — re-measure to confirm

(When ≤ 3 readings fail, the disposition names them inline instead: "…required at S6-G07 and S6-G11."; beyond 3 it defers to the list below.)

**Case 3 — all fail (example: 4,912 readings, all FAIL):**

> All 4,912 readings failed — the component is below the code minimum everywhere measured.
> Next action: take the component out of service and notify the responsible inspector.
> None of the 4,912 readings are ACCEPT. All are FAIL — wall is thinner than the code allows.
> *(worst-locations list: first 5 per the ordering above)*

Narrative sentences render only for non-zero counts (except the all-accept and all-fail collapsed forms above). `Infinity` / `NaN` never render.

## PDF Page 1 — Executive Dashboard

### Structure

`buildPdfDocument` splits into TWO `<Page size="A4">` elements. Every `<View>` row keeps `wrap={false}`. The fixed page-number footer (`FlawCheck Certified Inspection Report · Page N of M`) renders on both pages. Fonts: built-in Helvetica + Courier only; all styling through the existing `styles` object (no new metrics beyond section wrappers reusing `summaryCard`/`metaRow`/`footer` styles).

**Page 1 composition order (locked):**

1. Report header — existing title row (`FlawCheck Inspection Report` + sign-off chip) + meta row (GENERATED / SOURCE / EVALUATION DATE / REV + report ID). Unchanged.
2. **Disposition banner** (new) — full-width card reusing `styles.summaryCard`; heading is the existing disposition string (`ACTION REQUIRED — DEFECTS DETECTED` / `ATTENTION — RE-CHECK REQUIRED` / `ACCEPTABLE FOR CONTINUED SERVICE`, color `#991b1b` for the fail tone, `#047857` for the accept tone) with the locked sentence beneath (`styles.summaryStat`).
3. **Executive summary card** — the existing `EXECUTIVE EVALUATION SUMMARY` block (`styles.summaryCard`), moved onto page 1 unchanged (the optional copy fix "Total CMLs" → "Total readings" is in discretion and recommended).
4. **Code-breakdown stats** (new) — one `styles.grid` of label/value cells (`gridLabel`/`gridValue`): verdict counts (`{accept} Accept · {reCheck} Re-check · {fail} Fail`) plus governing-source breakdown — `vs pressure design (B31.3): {n} pass · {m} fail` and `vs structural minimum (API 574): {n} pass · {m} fail`, computed presentation-level by comparing each reading's `tActualMm` against `tPressureMm` and `tStructuralMm` at the 6-dp rounding convention. Counts reconcile with `summary.total`.
5. **Top-10 worst CMLs table** (new) — sourced from the governing ordering's first 10 rows (`getGoverningPdfReadings(snapshot.readings, 10)`; flagged rows in original order first, then accept remainder by RL ascending). Columns exactly: `CML / Location` (`styles.cellName`), `t-actual (mm)`, `t-required (mm)`, `RL (yr)`, `Verdict` (`styles.cellNum`; verdict may use `styles.cellWide`). RL cell reuses the register convention: `—` for null, `0.0 (RETIRED)` for ≤ 0, else 1 dp.
6. **What-to-do-next line** (new) — one `styles.summaryStat` sentence (copy below).
7. **"Full data" pointer** (new) — locked copy: `Full data: the complete register of {total} readings is available as a downloadable CSV export.` Static text (`styles.footer`) — no hyperlink, no endpoint exists this phase.
8. **Verdict glossary footer** — per the glossary contract above.

**Page 2 onward (unchanged content, new page):** Component context, PT/MT indication triage, governing CML measurements register (top 100 + all reject/re-check), clause-cited conclusions, next-inspection callout, audit appendix, inspector sign-off, disclaimer footer. The register remains the human-verifiable detail layer.

### Disposition banner copy contracts

| Case | Banner sentence (locked, beneath the existing heading string) |
|------|---------------------------------------------------------------|
| Any FAIL | `{fail} of {total} readings FAILED — the worst locations need immediate inspection.` |
| FAIL = 0, RE-CHECK > 0 | `{accept} of {total} readings meet the code minimum — {reCheck} readings need re-check before disposition.` |
| All ACCEPT | `All {total} readings meet the code minimum — acceptable for continued service.` |

### What-to-do-next copy contracts

| Case | Line (locked) |
|------|---------------|
| Any FAIL | `Immediate action: re-measure and disposition the failing locations before continued service.` |
| FAIL = 0, RE-CHECK > 0 | `Next action: re-check the flagged locations to confirm thickness before disposition.` |
| All ACCEPT | `Next action: continue the established inspection interval — earliest next inspection is dated in the register.` |

## Accessibility Floor (Phase 6 additions; inherits 02 items 1–10)

1. The brief is a single `<section aria-label="What we found">`; screen readers encounter disposition → next-action → narrative → worst list in DOM order, matching visual order.
2. The worst-locations list is a real `<ul>`/`<li>`; the verdict chip is text (chip contract) — color is never the sole channel.
3. Glossary legend lines are REAL TEXT on all three surfaces — never images, tooltips, or `title`-only.
4. Contrast: all new text meets the existing ≥ 4.5:1 floor — `text-muted-foreground` (dark `oklch(0.705 …)`) on `--card` passes; light-island glossary text on white passes; PDF `#444444`+ on white passes.
5. The PDF dashboard is selectable text (react-pdf `Text` nodes) — the glossary and banner are readable by copy/paste and screen-reader passthrough of the rendered PDF.
6. Both demo buttons are keyboard-operable, disabled during parsing (`disabled:opacity-50`, excluded from tab order), and announce completion via the existing `role="status"` parsing line.

## What the Developer Cannot Change

1. **The brief's position, structure, and citation-free invariant** — below the hero card, above the KPI cards, `bg-card border-border rounded-xl p-6`, `aria-label="What we found"`, `text-lg` disposition line, ZERO citations in the brief body.
2. **The brief's determinism** — composed by a pure TypeScript template from `evaluate()` output; no LLM writes the summary of record.
3. **The locked copy contracts** — the three brief cases, the three banner sentences, the three what-to-do-next lines, the CSV pointer wording, the glossary plain sentences (verbatim).
4. **The glossary citation ids and mechanism** — `api574_10_5_1_4` / `api570_7_1_2_governing` / `api570_7_6`, rendered only through `citationRef`; hardcoded clause strings are forbidden; `citations.json` is renderer-locked and may not gain ids in this phase.
5. **Chip strings** — `ACCEPT / RE-CHECK / FAIL` in `verdict-chip.tsx` are repo-protected; the glossary adds lines, never renames chips.
6. **PDF structure** — two `<Page>` elements, page-1 composition order, built-in Helvetica/Courier with no `Font.register`, `wrap={false}` rows, top-10 sourced from the governing ordering.
7. **Engine and criteria sovereignty** — no change to any number computed by `lib/calc/` (golden-pinned), the verdict banding order, the governing `t_required` rule, or `lib/criteria/` mechanics; the brief/dashboard are pure compositions of existing fields.
8. **Demo composition** — the subset filters by Tank identity (never date), preserves the six-column schema and per-CML multi-campaign history through the same parse path; the full 4,912-row fixture and its tests stay untouched; the secondary button uses secondary styling, never accent.
9. **The token system and contrast floor** — no new colors, no new fonts, no spacing outside the 4px scale, ≥ 4.5:1 contrast on every new surface.
10. **Scope fences** — no charts/graphs, no branding badges, no pipeline graph, no interactive tooltips, no CSV export endpoint.
