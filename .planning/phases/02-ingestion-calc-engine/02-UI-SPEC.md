# Phase 2 — UI Design Contract

> Visual and interaction contract for the Phase 2 wizard surfaces (Screen 1 Ingestion, Screen 2 Review & Metadata, Screen 3 read-only Results). Generated by gsd-ui-researcher; verified by gsd-ui-checker; consumed by gsd-planner, gsd-executor, gsd-ui-auditor.
>
> **Out of scope (later phases):** streaming reasoning pane (Phase 3), PDF/print report (Phase 4), landing polish / demo-mode toggle chrome (Phase 5). Phase 2 ships no dead buttons for these — no "Download PDF", no reasoning tab.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn deliberately **not** initialized. CONTEXT.md locks: ANY new package requires explicit user approval (checkpoint). Phase 2 uses plain Tailwind 4 utilities + small local components. |
| Preset | not applicable |
| Component library | none (no radix / base-ui). Hand-rolled local components under `components/`. |
| Icon library | none — inline SVG only, 16px / 20px, stroke 1.5, `currentColor`. No icon package. |
| Font | Geist Sans (UI) / Geist Mono (all numeric table data) — already wired via `next/font` in `app/layout.tsx`; no font changes. |
| Styling | Tailwind 4 CSS-first (`@import "tailwindcss"` + `@theme`), dark theme **forced** (see below) |

**Theme baseline (dark, forced).** The Phase 1 scaffold ships a dark palette behind `prefers-color-scheme`. Phase 2 is a projector-first engineering tool: the dark palette becomes unconditional. In `app/globals.css`, set `:root` to the dark values and drop the media-query flip; new Phase 2 components use the semantic tokens below, **never** `dark:` variants. Implementation may be `@theme inline` tokens or the literal hex — the contract is the hex + the class strings given in the chip table.

```css
:root {
  --background: #0a0a0a;      /* page */
  --foreground: #ededed;      /* primary text */
  --surface: #171717;         /* cards, table header, panels */
  --border: #262626;          /* hairlines, input borders */
  --muted: #a3a3a3;           /* captions, secondary text */
  --accent: #2563eb;          /* primary actions only (see Color) */
  --accept: #4ade80;          /* verdict text: ACCEPT */
  --recheck: #fbbf24;         /* verdict text: RE-CHECK */
  --fail: #f87171;            /* verdict text: FAIL */
  --destructive: #dc2626;     /* destructive button only */
}
```

`status: resolved (inferred)` — forcing dark (vs media-query) is the simplest option consistent with the locked "dark theme per scaffold" baseline and demo-video use; the scaffold already owns these exact hex values.

## Verdict & Flag Chip Contract

### Verdict chips (CML table + PT/MT triage)

Base class (both): `inline-flex h-6 items-center gap-1 rounded-full border px-2 text-xs font-semibold uppercase tracking-wide`

| Verdict | Exact label | Classes | Hex (text / bg-alpha / border) | Condition (locked, `ut-criteria.json` boundary convention, evaluated in exactly this order) |
|---------|-------------|---------|-------------------------------|------------------------------|
| Accept | `ACCEPT` | `bg-green-500/10 text-green-400 border-green-500/30` | #4ade80 / #22c55e@10% / #22c55e@30% | `t_actual >= t_required + gauge_uncertainty` |
| Re-check | `RE-CHECK` | `bg-amber-500/10 text-amber-400 border-amber-500/30` | #fbbf24 / #f59e0b@10% / #f59e0b@30% | `t_required <= t_actual < t_required + gauge_uncertainty` — **exact equality with t_required is RE-CHECK, not FAIL**; `t_actual == t_required + uncertainty` is ACCEPT |
| Fail | `FAIL` | `bg-red-500/10 text-red-400 border-red-500/30` | #f87171 / #ef4444@10% / #ef4444@30% | `t_actual < t_required` |

Note: the calc engine's internal band name is `reject` (`ut-criteria.json`); the UI label is always `FAIL`. Chip text is the semantics — color is redundant (color-blind and forced-colors safe).

### PT/MT indication chips (same base + same three labels, mapped from `ptmt-criteria.json`)

| Condition | Chip | Detail line rendered under the card |
|-----------|------|-------------------------------------|
| Non-relevant: max dimension <= 1.5 mm, not crack-suspect | `ACCEPT` | "Non-relevant per relevance threshold (1.5 mm)." |
| Non-relevant but marked crack-suspect | `RE-CHECK` | "Verify crack-suspect indication with Level 2/3 inspector." |
| Relevant linear (L > 3W) | `FAIL` | "Relevant linear indications are rejected — escalate to Level 2/3 inspector evaluation." |
| Relevant rounded > 5.0 mm | `FAIL` | "Rounded indication exceeds 5.0 mm limit." |
| >= 4 relevant rounded indications in a line, edge-to-edge separation <= 1.5 mm | `FAIL` | "Aligned rounded cluster: {count} indications within 1.5 mm separation." |

Each triage card also renders its clause ref: MT → "ASME B31.3 §344.3.2", PT → "ASME B31.3 §344.4.2" (auto from method). `RE-CHECK` for crack-suspect is the only inferred mapping (the criteria config has no amber band); everything else is direct from `ptmt-criteria.json`. `status: resolved (inferred)` for the crack-suspect row.

### Flag chips (data-quality — visually distinct: rounded-rect, not pill)

Base class: `inline-flex h-6 items-center rounded border px-2 text-xs font-semibold uppercase tracking-wide`

| Flag | Exact label | Classes |
|------|-------------|---------|
| Outlier / re-shoot candidate | `OUTLIER` | `border-amber-500/40 text-amber-400` |
| Negative apparent corrosion rate | `MEASUREMENT INCONSISTENCY` | `border-amber-500/40 text-amber-400` |
| No corrosion history available | `INSUFFICIENT HISTORY` | `border-gray-600 text-gray-400` |

## Screen Layout Contracts

Wizard chrome (all screens): header row with app name `FlawCheck` + muted subtitle `NDT Inspection Copilot`; step indicator below; content container `max-w-4xl` centered for Screens 1–2, `max-w-6xl` for Screen 3 (wide table). Navigation: back allowed (2→1, 3→2) preserving state; forward only via CTAs.

### Screen 1 — Landing & Ingestion

Regions, top to bottom:
1. Step indicator — step 1 active (accent), 2–3 muted.
2. Heading `Ingest inspection data` (20px/600) + one muted line: `Upload an ultrasonic thickness register to evaluate against API 570 / ASME B31.3.`
3. **Dropzone** (primary region): dashed 2px border `border-gray-700`, `min-h-40`, centered content (20px SVG upload icon, heading, sub-link). Click / Enter / Space opens file browse (`accept=".csv,text/csv"`).
4. Divider with centered `or` (muted, 12px).
5. **Primary CTA** `Load Demo Scenario` — accent button, visually dominant.
6. Secondary row: `Download sample CSV` link + `View format guide` collapsible.

States:

| State | Behavior |
|-------|----------|
| Empty (initial) | As above — this is the only first-run state |
| Loading (parsing) | Dropzone + demo button `disabled`; `role="status"` line `Parsing {filename}…` |
| Error: invalid file | Inline error under dropzone (copy above); dropzone unchanged; no navigation |
| Error: parse failure | Error panel replaces dropzone content: parse-failure copy + first errors as `line {n} — {problem}` + `Try another file` button returning to empty state |
| Error: zero data rows | Same error panel pattern with the zero-rows copy |
| Success | Navigate to Screen 2; focus moves to its heading |

### Screen 2 — Data Review & Component Metadata

Regions, top to bottom:
1. Step indicator — step 2 active. Demo banner if applicable.
2. **Session summary bar** (surface card): filename, row count, detected CSV thickness unit, `sample data` tag when demo.
3. **Column mapping panel** (surface card): one dropdown per target field (table below), required fields marked `*`. Unmapped required fields render the dropdown border `border-red-500/50` and are listed in a `role="alert"` banner above the panel. The CSV **thickness unit** select sits in this panel (auto-guessed from header suffix `_mm` / `_in` / `_mils`, default mm).
4. **Parsed-row table** (surface card): paginated 50 rows/page, caption `Showing 1–50 of 4,912`. First columns = mapped identity fields (editable inline `text-sm` inputs); last column = row status badge. Error rows: badge + red left border `border-l-2 border-l-red-500/60`. Valid rows: no badge.
5. **Metadata form** (surface card): see Interaction Contracts for fields + validation.
6. **Sticky footer action bar**: left = validation summary in plain text (`3 row errors · 1 unmapped column` or `All checks passed`); right = `Run Evaluation` (accent, disabled while any blocker exists).

States:

| State | Behavior |
|-------|----------|
| Empty | Unreachable (entry requires a parsed file) — if state is lost, redirect to Screen 1 |
| Loading | Table skeleton not needed (parse is local + fast): mapping panel renders immediately post-parse; `Run Evaluation` disabled until checks pass |
| Error (validation) | Blocking banner(s) + per-row/per-field errors as specified; `Run Evaluation` disabled |
| Error (evaluation failure) | Error banner in footer bar with evaluation-failure copy; button re-enabled |
| Loading (evaluating) | `Run Evaluation` shows `Evaluating…`, disabled |
| Success | Navigate to Screen 3; focus moves to its heading |

### Screen 3 — Evaluation Results (read-only)

Regions, top to bottom:
1. Step indicator — step 3 active. Demo banner if applicable.
2. **Summary strip** (surface card): `4,912 readings · 12 locations — 3,900 ACCEPT · 800 RE-CHECK · 212 FAIL` (counts with mini verdict chips; mono numerals).
3. **CML results table** (primary region), paginated 50/page. Columns (exact order):

| Column | Content | Format |
|--------|---------|--------|
| CML / Location | Identity from mapped Tank + Grid Position / Reading ID | text, `truncate` + `title` |
| t-actual (mm) | measured thickness | mono, 2 dp |
| t-required (mm) | computed `max(t_pressure, t_structural)` | mono, 2 dp |
| CR_LT (mm/yr) | long-term rate, API 570 §7.1.2 | mono, 3 dp, or `—` |
| CR_ST (mm/yr) | short-term rate | mono, 3 dp, or `—` |
| CR governing (mm/yr) | `max(LT, ST)` after clamp | mono, 3 dp, weight 600 |
| RL (yr) | remaining life | mono, 1 dp, or `—` + `insufficient corrosion history` sub-text |
| Next inspection | measurement date + interval, API 570 §6.3.3 / Table 1 | `YYYY-MM-DD` + muted `(interval {x.x} yr)`, or `—` |
| Flags | flag chips (see Flag Chip Contract) | chips; chip press toggles inline detail row |
| Verdict | verdict chip | chip |

4. **PT/MT triage list**: one surface card per indication: `[PT]` method tag (neutral) — morphology + dimensions (`Linear indication L 4.2 × W 0.8 mm`) — verdict chip — muted rule line (detail copy from chip table + clause ref). Empty state per Copywriting Contract.
5. **Footnotes** (muted, 12px): unit-assumption footnote + data source line (`Source: {filename} · {n} rows · evaluated {YYYY-MM-DD HH:mm}`).

States: Success (above) is the only populated state; Loading reuses Screen 2's evaluating state (this screen renders after it); Error surfaces back on Screen 2's footer. No Phase 3/4 affordances.

## Interaction Contracts

### Dropzone (Screen 1)
- **Idle:** dashed border `border-gray-700`; content per layout contract.
- **Dragover:** `border-blue-500 bg-blue-500/5`; reverts on `dragleave`/`drop`. Keyboard parity: the whole dropzone is a real `<button>`; Enter/Space open browse. Drag is never the only path.
- **Invalid file:** client-side extension/type check before parse → inline error, no state change.
- **Duplicate / replace:** drop or browse while rows are loaded (from Screen 2's back-navigation or a second drop) → modal confirm `Replace loaded data?` (copy above). Cancel keeps everything; Replace clears rows + metadata + mapping and re-enters parsing. Dialog: focus trapped, initial focus on `Cancel`, Esc = Cancel.
- **Demo button:** loads the committed Zenodo subset with zero network beyond page load (locked); behaves exactly like a successful parse and sets the demo provenance banner.

### Column mapping (Screen 2)
Target fields and auto-guess aliases (match on normalized header: lowercase, strip non-alphanumerics/underscores):

| Field | Required | Auto-guess aliases |
|-------|----------|--------------------|
| Reading ID | yes | `readingid`, `id`, `pointid`, `cml`, `gridposition` |
| Measured Thickness | yes | `measuredthicknessmm`, `measuredthickness`, `thickness`, `wallthickness`, `tactual` |
| Measurement Date | yes | `measurementdate`, `date`, `inspectiondate` |
| Original / Initial Thickness (t-initial) | no — CR_LT requires it | `originalscantlingmm`, `originalscantling`, `initialthickness`, `tinitial` |
| Previous Thickness (t-previous) | no — CR_ST requires it | `previousthickness`, `tprevious`, `lastthickness` |
| Tank / Location | no | `tank`, `location`, `component`, `cml` |

- **Override:** every dropdown lists all CSV headers + `— not mapped —`; changing any mapping re-runs row validation immediately.
- **Blocking state:** `Run Evaluation` disabled while any required field is unmapped; `role="alert"` banner lists each unmapped required field with the unmapped-column copy.
- **CR degradation (locked policy):** t-initial unmapped → CR_LT renders `—`; t-previous unmapped → CR_ST renders `—`; both unmapped → governing `—` + `INSUFFICIENT HISTORY` flag. Verdicts still compute (they need only t-actual + metadata).

### Row validation (Screen 2)
Badge types: `ERROR` (red, blocks), `WARNING` (amber, does not block), none for valid rows. Error catalog (specific, loud — never silent garbage):

| Trigger | Severity | Message (`Row {n}: {field} — {problem} ({value}).`) |
|---------|----------|------------------------------------------------------|
| Non-numeric thickness/date | ERROR | `…— not a number ('abc').` |
| Blank required cell | ERROR | `…— missing value.` |
| Thickness <= 0 | ERROR | `…— impossible value, must be greater than 0 (0 mm).` |
| Thickness >= outer diameter | ERROR | `…— impossible value, exceeds outer diameter ({v} mm).` |
| Unparseable date | ERROR | `…— not a valid date ('31/02/2026').` |
| Future-dated reading | WARNING | `…— date is in the future.` |
| Duplicate Reading ID | WARNING | `…— duplicate reading ID ('{id}').` |

### Metadata form (Screen 2)
Global unit selector at the top of the form — segmented control `mm | in | mils`, default `mm` — applies to all numeric metadata fields (mixed units are impossible by construction; the CSV thickness unit is declared separately in the mapping panel, and differing declared units are legal, converted to canonical mm, and surfaced in the results footnote).

| Field | Control | Default | Validation + error copy |
|-------|---------|---------|--------------------------|
| Outer diameter (OD) | number input | — | required, > 0. `Outer diameter must be a number greater than 0.` |
| Nominal thickness (t-nom) | number input | — | required, > 0, < OD. `Nominal thickness must be smaller than the outer diameter.` |
| Future corrosion allowance (FCA) | number input | `0` | >= 0. `FCA cannot be negative.` |
| Structural min thickness (t-structural) | number input | `0` | >= 0; 0 = not governing. Caption: `From API 574 Annex D tables — leave 0 if not applicable.` |
| Design Code | select | `ASME B31.3 — 2024 Edition` | required; sole v1 option (edition-pinned per `citations.json`) |
| Piping Class | select | placeholder `Select class` | required, options `Class 1 / Class 2 / Class 3`. `Select a piping class.` |
| Gauge uncertainty | number input, step 0.05 | `0.1` | >= 0. `Gauge uncertainty cannot be negative.` Label: `Gauge uncertainty (± {unit})` |

**Design conditions subgroup** — `status: resolved (inferred)` with rationale: the locked rule `t_required = max(t_pressure, t_structural)` (`ut-criteria.json` governing_t_required, API 574 §10.5.1.4) is not computable from the handoff field list alone; these are the minimal inputs the formulas require:

| Field | Control | Default | Validation |
|-------|---------|---------|------------|
| Design pressure (P) | number input | — | required, > 0. `Design pressure must be a number greater than 0.` |
| Allowable stress (S) | number input | — | required, > 0. `Allowable stress must be a number greater than 0.` |
| Advanced: E, W, Y | collapsed `<details>` | `1.0 / 1.0 / 0.4` | numbers > 0 (defaults per `ut-criteria.json` symbols: seamless, normal temperature, ferritic steel) |

### PT/MT entry (Screen 2, optional section)
- **Free-text notes textarea** (locked field): label `PT/MT notes (optional)`, 14px, carries into the evaluation session verbatim (ING-04). No validation.
- **Structured indication repeater** — `status: resolved (inferred)` with rationale: CALC-02 (Phase 2) requires per-indication verdicts, which `ptmt-criteria.json` can only compute from structured dimensions; the textarea alone cannot be deterministically triaged. `Add indication` button appends a row: Method (PT/MT radio), Morphology (Linear/Rounded radio), Length mm, Width mm, Count (default 1), Edge separation mm (shown only when Count >= 2), Description (optional). Numbers must be > 0. Rows removable (only non-destructive action without confirm).

### Data-quality flag display (Screen 3)
- Flag chips render in the Flags column; pressing a chip toggles an inline detail row beneath the CML row (`aria-expanded` + `aria-controls` on the chip button).
- **Measurement inconsistency detail (locked negative_cr_policy):** shows both values — `Raw CR {LT/ST}: −0.12 mm/yr · clamped to 0.00 mm/yr for remaining life` + sentence `Apparent thickness gain detected — possible measurement-point drift, re-coating, or gauge noise.` RL is computed from the clamped rate; raw rates stay visible in CR_LT/CR_ST cells. Never `Infinity`.
- **Outlier detail (locked CALC-04):** `Reading deviates from CML population — re-shoot candidate.` The verdict chip still renders; outliers warn, they do not override the banding.
- **Insufficient history:** RL + Next inspection render `—` with muted sub-text `insufficient corrosion history` and the `INSUFFICIENT HISTORY` chip. The strings `Infinity` / `NaN` must never render anywhere in the results table.

## Accessibility Floor

1. Every input/select/textarea has a persistent visible `<label>`; placeholders are never the only label.
2. Focus order = DOM order = visual order (top-to-bottom). Visible `:focus-visible` ring (2px accent) on all interactive elements.
3. Dropzone operable by keyboard (Enter/Space open browse); drag is an enhancement, never the only path.
4. Live regions: `role="alert"` for unmapped-required banner, row-error summary, metadata errors, parse failure, evaluation failure; `role="status"` (polite) for parsing progress and evaluation completion.
5. Verdict/flag chips carry their meaning as text — color is never the sole channel.
6. Data tables are real `<table>` elements with `<th scope="col">`; flag detail rows are toggled by buttons with `aria-expanded`/`aria-controls`; row errors linked to cells via `aria-describedby` + `aria-invalid="true"`.
7. Contrast: all text >= 4.5:1 against `#0a0a0a` / `#171717` (muted `#a3a3a3` passes; chip text colors green-400/amber-400/red-400 pass).
8. After step transitions, focus moves to the new screen's `<h1>` (`tabIndex={-1}`).
9. Confirm dialog: focus trap, Esc cancels, initial focus on the safe action (`Cancel`).
10. `Run Evaluation` and `Load Demo Scenario` disabled states use `disabled:opacity-50` (scaffold pattern) and are excluded from tab order.
